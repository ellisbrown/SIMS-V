# Getting started

SIMS-V records room-scale walkthroughs in procedural AI2-THOR houses. This
guide covers environment setup, the two supported house sources, and trajectory
generation. See the [QA pipeline](qa-pipeline.md) after videos have been
recorded.

## Requirements

- Python 3.9
- [`uv`](https://docs.astral.sh/uv/)
- HTTPS access for the first dependency, simulator, and dataset downloads
- A supported AI2-THOR graphics backend: desktop rendering on macOS or Vulkan
  on Linux (NVIDIA is tested and strongly recommended)
- `ffmpeg` for video encoding

Without CUDA, trajectory generation defaults to one worker; AI2-THOR still
needs the graphics backend above. QA question generation, combination, and
formatting can run on CPU, while spatial-metadata extraction also initializes
AI2-THOR. Cluster users should first check the [headless GPU guidance](cluster.md).

## Install

From a source checkout:

```bash
uv sync --locked
uv run python -m nltk.downloader wordnet wordnet2022
uv run sims-v --help
```

Use the lockfile rather than `pip install`; it pins the simulator and supporting
research dependencies used by this repository.

## Generate a small ProcTHOR walkthrough

ProcTHOR houses are downloaded on first use and do not require the larger
Objaverse asset bundle:

```bash
uv run sims-v generate \
    --dataset-dir outputs/procthor-demo \
    --house-dataset procthor \
    --split val \
    --max-houses 1 \
    --trajectories-per-house 1
```

Generation visits each room, records a panoramic scan, and writes one directory
per successful house. The principal output will resemble:

```text
outputs/procthor-demo/
├── constants.yaml
├── generation_logs/
└── val/
    └── 000000/
        ├── house_spec.json
        ├── rgb__0.mp4
        ├── offline_annos__0.jsonl
        ├── hdf5_sensors.hdf5
        └── success.txt
```

The default writes only the primary RGB video. Frame-level annotations needed
for QA and the compact HDF5 sensor record are still written. Add only the
alternative videos you need:

```bash
uv run sims-v generate \
    --dataset-dir outputs/procthor-depth-demo \
    --extra-video-modalities depth semantic_seg
```

Use `--extra-video-modalities all` for the complete diagnostic and ablation
bundle. The main [README](../README.md#what-is-generated) describes every
choice.

`--max-houses` counts candidate houses. A house can be rejected when the robot
cannot initialize or complete the walkthrough, so check the final success count
before using a generated corpus.

## Use the ProcTHOR-Objaverse houses

The paper's main visual data use the public Objaverse SIMS bundle: processed 3D
assets, generated houses, and ProcTHOR placement databases. The download is
approximately 30 GB; allow about 60 GB while retaining and extracting the
archives.

```bash
uvx --from huggingface-hub hf download ellisbrown/objaverse_sims \
    --repo-type dataset \
    --revision 9087d8d6df551c3ad0af85b1e2b24fa6f654ae7d \
    --local-dir ./objaverse_sims

for archive in ./objaverse_sims/processed/shard_*.tar; do
    tar -xf "$archive" -C ./objaverse_sims/processed
done

uv run python scripts/verify_objaverse_dataset.py
```

The standard `./objaverse_sims` location is detected automatically. For a
different location, pass `--objaverse-dir /path/to/objaverse_sims` to the
verifier and generation commands, or set `OBJAVERSE_DATA_DIR`:

```bash
uv run python scripts/verify_objaverse_dataset.py \
    --objaverse-dir /path/to/objaverse_sims

uv run sims-v generate \
    --dataset-dir outputs/objaverse-demo \
    --house-dataset objaverse \
    --objaverse-dir /path/to/objaverse_sims \
    --max-houses 1 \
    --trajectories-per-house 1
```

The expected asset layout is:

```text
objaverse_sims/
├── processed/
├── houses/
│   ├── train.jsonl.gz
│   ├── val.jsonl.gz
│   └── test.jsonl.gz
└── procthor_databases/
    ├── asset-database.json
    ├── material-database.json
    ├── placement-annotations.json
    └── receptacles.json
```

## Generation options

The most useful controls are:

- `--trajectories-per-house`: repeated walkthroughs with independently sampled
  starting poses
- `--max-steps`: maximum agent actions in each walkthrough
- `--resolution-scale`: multiplier on the default 396x224 controller render;
  raw navigation RGB crops six pixels from each horizontal edge (384x224 at
  scale 1), while optional modalities retain the controller dimensions
- `--quality`: AI2-THOR rendering quality
- `--extra-video-modalities`: optional depth, segmentation, edge, and masked
  videos; none are generated by default, and `all` selects every modality
- `--material-randomization-probability`: probability of randomizing materials
  after loading a house
- `--rotation-noise-std-degrees`: optional Gaussian yaw noise; disabled by
  default
- `--workers`: explicit worker count instead of automatic GPU/memory inference

The defaults favor a small first run with additional material and rotation
randomization disabled. The settings used for the paper are recorded separately
in [paper settings](paper-settings.md).

## Resume behavior

Rerunning the same command in the same `--dataset-dir` skips completed houses.
`constants.yaml` records output-defining settings and prevents an accidental
resume with incompatible parameters. Use a new output directory when changing
the house source, trajectory count, rendering, or randomization settings.

## Generate video QA

Once trajectories exist, run the four-stage QA pipeline:

```bash
uv run sims-v qa \
    --dataset-dir outputs/objaverse-demo \
    --split val \
    --question-types vsi_obj_count
```

If the Objaverse bundle is outside `./objaverse_sims` and you did not set
`OBJAVERSE_DATA_DIR`, repeat `--objaverse-dir /path/to/objaverse_sims` on this
command. Generation and QA run in separate processes.

This extracts spatial metadata, generates per-video questions, combines the
records, and writes training JSONL under `qas/val/rgb/`. See
[QA pipeline](qa-pipeline.md) for other question types and stage controls.

## Troubleshooting

- `libvulkan.so.1` or `ERROR_INCOMPATIBLE_DRIVER`: the GPU driver is present
  but the Vulkan loader or ICD is unavailable; see [cluster setup](cluster.md).
- Anonymous GitHub API rate limit: public data do not require authentication,
  but setting `GITHUB_TOKEN` can raise the limit used by `prior`.
- Missing Objaverse files: rerun `scripts/verify_objaverse_dataset.py` with the
  correct `--objaverse-dir`.
- No successful houses: inspect `generation_logs/logs.tsv` and reduce workers
  if simulator processes exhaust GPU memory.
